SECTION 1: DIRECTORY STRUCTURE
═══════════════════════════════════════════════════════════════

public/data/{slug}/
├── assembly.json          ← assembly metadata
├── parts.json             ← part records (what each part IS)
├── placements.json        ← spatial data (where each part LIVES)
├── diagram.png            ← source fiche image (original, unmodified)
└── parts/
    ├── 001.png            ← segmented part cutout, label "1"
    ├── 002.png            ← segmented part cutout, label "2"
    └── ...

RULES:
  - Slug format: {brand}-{model}-{year}-{assembly}, all lowercase, hyphens only
    Example: ktm-500-exc-f-2025-clutch
  - diagram.png is ALWAYS the original — never overwrite it
  - parts/ directory is ALWAYS generated by segment_parts.py
  - parts/ filenames are ALWAYS label.zfill(3) + ".png"
    Label "1"  → parts/001.png
    Label "10" → parts/010.png
    Label "1a" → parts/1a0.png  (non-numeric: use label + "00")

SECTION 2: assembly.json
═══════════════════════════════════════════════════════════════

PRODUCED BY: placement-tool.html (Export Assembly JSON button)
CONSUMED BY: viewer (RallyViewer.load, createWorldMapper)

SCHEMA:
{
  "slug":           string,    // REQUIRED. matches directory name exactly
  "brand":          string,    // REQUIRED. e.g. "KTM"
  "model":          string,    // REQUIRED. e.g. "500 EXC-F"
  "year":           integer,   // REQUIRED. e.g. 2025
  "assembly":       string,    // REQUIRED. e.g. "CLUTCH"
  "diagram_image":  string,    // REQUIRED. always "diagram.png"
  "canvas": {
    "width":        integer,   // REQUIRED. natural pixel width of diagram.png
    "height":       integer    // REQUIRED. natural pixel height of diagram.png
  },
  "viewer_defaults": {
    "world_height":           number,   // default 10. Three.js world units tall
    "world_depth":            number,   // default 5.  Z-axis range
    "explode_distance":       number,   // default 2.0. scalar on explode_vector
    "show_background_diagram": boolean  // default true
  },
  "source": {
    "provider":     string,    // e.g. "judd_racing", "partzilla", "manual"
    "url":          string     // source URL or "" if manual
  }
}

EXAMPLE:
{
  "slug": "ktm-500-exc-f-2025-clutch",
  "brand": "KTM",
  "model": "500 EXC-F",
  "year": 2025,
  "assembly": "CLUTCH",
  "diagram_image": "diagram.png",
  "canvas": { "width": 1600, "height": 1200 },
  "viewer_defaults": {
    "world_height": 10,
    "world_depth": 5,
    "explode_distance": 2.0,
    "show_background_diagram": true
  },
  "source": { "provider": "manual", "url": "" }
}

SECTION 3: parts.json
═══════════════════════════════════════════════════════════════

PRODUCED BY: scraper / manual entry
CONSUMED BY: viewer (InfoPanel, partsByLabel map)

NOTE: parts.json describes WHAT a part is.
      placements.json describes WHERE it appears in THIS diagram.
      They are joined on "label" at runtime.

SCHEMA (array of):
{
  "label":          string,    // REQUIRED. matches placements.json label exactly
  "part_number":    string,    // REQUIRED. OEM part number
  "name":           string,    // REQUIRED. uppercase part name
  "qty":            string,    // REQUIRED. quantity as string e.g. "1", "8"
  "notes":          string,    // optional. service notes
  "superseded_by":  string,    // optional. part_number this was replaced by, or ""
  "assembly_slug":  string     // REQUIRED. matches assembly.json slug
}

EXAMPLE:
[
  {
    "label": "4",
    "part_number": "78032011000",
    "name": "FRICTION DISC",
    "qty": "8",
    "notes": "Min thickness 2.7mm. Replace as set.",
    "superseded_by": "",
    "assembly_slug": "ktm-500-exc-f-2025-clutch"
  }
]

SECTION 4: placements.json
═══════════════════════════════════════════════════════════════

PRODUCED BY: placement-tool.html (Export placements.json button)
CONSUMED BY: viewer (loadTextures, explode logic)
ALSO CONSUMED BY: segment_parts.py (reads bbox to crop diagram)

THIS IS THE MOST CRITICAL CONTRACT FILE.
All coordinates are normalized (0.0–1.0) relative to diagram.png dimensions.
Never store raw pixel values.

SCHEMA (array of):
{
  "label":          string,    // REQUIRED. must match parts.json label exactly
  "x":              number,    // REQUIRED. normalized center X of bounding box
  "y":              number,    // REQUIRED. normalized center Y of bounding box
  "z":              number,    // REQUIRED. depth within assembly. 0 = midplane.
                               //           positive = toward viewer (front)
                               //           negative = away from viewer (rear)
  "depth_order":    integer,   // REQUIRED. render order. higher = drawn on top.
                               //           use 10,20,30 spacing for flexibility
  "explode_vector": [x, y, z], // REQUIRED. direction + magnitude to explode.
                               //           applied as: pos + vector * explode_distance
                               //           Y-axis is NOT flipped here — the viewer
                               //           handles the flip internally.
  "segment_image":  string,    // REQUIRED. relative path from assembly dir.
                               //           always "parts/{label.zfill(3)}.png"
  "bbox": {
    "x":            number,    // REQUIRED. normalized left edge of crop box
    "y":            number,    // REQUIRED. normalized top edge of crop box
    "w":            number,    // REQUIRED. normalized width of crop box
    "h":            number     // REQUIRED. normalized height of crop box
  },
  "anchor": {
    "x":            number,    // default 0.5. horizontal anchor within sprite
    "y":            number     // default 0.5. vertical anchor within sprite
  }
}

EXPLODE VECTOR CONVENTIONS:
  Parts above assembly center:  y > 0  (e.g. [0, 1.5, 0])
  Parts below assembly center:  y < 0  (e.g. [0, -1.2, 0])
  Parts left of center:         x < 0  (e.g. [-0.8, 0, 0])
  Parts right of center:        x > 0  (e.g. [0.8, 0, 0])
  Outermost cover (front):      z > 0  (e.g. [0, 0, 0.4])
  Innermost components:         z < 0  (e.g. [0, 0, -0.2])
  Center/fixed parts:           [0, 0, 0]

DEPTH ORDER CONVENTIONS:
  Outer cover:     90
  Gasket:          80
  Pressure plate:  70
  Friction discs:  60
  Steel discs:     50
  Inner hub:       40
  Basket:          30
  Shaft/gear:      20
  Bearings:        10

EXAMPLE:
[
  {
    "label": "1",
    "x": 0.412,
    "y": 0.188,
    "z": 0.4,
    "depth_order": 90,
    "explode_vector": [0.0, 0.0, 1.2],
    "segment_image": "parts/001.png",
    "bbox": { "x": 0.36, "y": 0.14, "w": 0.11, "h": 0.09 },
    "anchor": { "x": 0.5, "y": 0.5 }
  }
]

SECTION 5: SEGMENT FILENAME RULES
═══════════════════════════════════════════════════════════════

PRODUCED BY: placement-tool.html (auto-set segment_image field)
CONSUMED BY: segment_parts.py (output filename)
CONSUMED BY: viewer (loadTextures)

RULE: segment_image = "parts/" + label.zfill(3) + ".png"

  label "1"   → "parts/001.png"
  label "10"  → "parts/010.png"
  label "11a" → "parts/11a.png"  (non-numeric: use label as-is, no padding)

segment_parts.py implements this same rule.
placement-tool.html sets segment_image using this same rule.
The viewer loads segment_image verbatim — it does not construct the path itself.

SECTION 6: COORDINATE SYSTEM
═══════════════════════════════════════════════════════════════

DIAGRAM SPACE (placement-tool.html):
  Origin: top-left of image
  X: 0.0 (left) → 1.0 (right)
  Y: 0.0 (top)  → 1.0 (bottom)

THREE.JS WORLD SPACE (viewer):
  Origin: center of scene
  X: -worldWidth/2 (left) → +worldWidth/2 (right)
  Y: +worldHeight/2 (top) → -worldHeight/2 (bottom)   ← Y IS FLIPPED
  Z: -worldDepth/2 (back) → +worldDepth/2 (front)

CONVERSION (in loaders.js createWorldMapper.toWorld):
  world_x = (norm_x - 0.5) * worldWidth
  world_y = (0.5 - norm_y) * worldHeight    ← flip Y here
  world_z = norm_z * worldDepth

EXPLODE VECTOR Y-FLIP:
  In placements.json, explode_vector[1] uses DIAGRAM convention:
    positive Y = downward in diagram = downward in real life
  The viewer flips it: vec.y = -placement.explode_vector[1]
  So [0, 1, 0] in placements.json means "explode upward" in the viewer.
  Author explode vectors thinking about physical direction, not screen direction.

SECTION 7: WHAT EACH TOOL OWNS
═══════════════════════════════════════════════════════════════

placement-tool.html:
  READS:   nothing (standalone)
  WRITES:  placements.json, assembly.json

segment_parts.py:
  READS:   placements.json, assembly.json, diagram.png
  WRITES:  parts/001.png ... parts/NNN.png
  NEVER:   modifies placements.json or assembly.json

viewer (Vite):
  READS:   assembly.json, parts.json, placements.json, parts/*.png
  WRITES:  nothing
  NEVER:   constructs file paths beyond what segment_image specifies

SECTION 8: VALIDATION CHECKLIST
═══════════════════════════════════════════════════════════════

Before running segment_parts.py, verify:
  [ ] placements.json exists in assembly dir
  [ ] assembly.json exists and canvas.width/height match actual diagram.png
  [ ] diagram.png exists
  [ ] every placement has: label, x, y, z, depth_order, explode_vector,
      segment_image, bbox (with x,y,w,h), anchor
  [ ] no two placements share the same label
  [ ] all bbox values are 0.0–1.0
  [ ] bbox.x + bbox.w <= 1.0 for all placements
  [ ] bbox.y + bbox.h <= 1.0 for all placements

Before running viewer, verify:
  [ ] parts/*.png exist for every segment_image referenced in placements.json
  [ ] parts.json labels match placements.json labels (join will be silent on miss)
  [ ] assembly.json slug matches directory name exactly
